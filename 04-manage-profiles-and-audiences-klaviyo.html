Manage Profiles & Audiences — mapped to Klaviyo's API

Two skills, one spec. "Manage Profiles" and "Manage Audiences" each carry their own expected shapes and failure modes — here's what they found when matched against Klaviyo's real OpenAPI spec.

SKILL
Manage Profiles expects three operations — upsert, delete, and bulk read — each with a known shape and known failure modes. Below, every endpoint, parameter, and rate limit came directly from Klaviyo's published OpenAPI spec. Nothing here was inferred from prose. The warnings are the skill's prior knowledge of where integrations like this tend to break.
1
Upsert a profile
Create if new, update if it already exists
1 call · from spec
POST https://a.klaviyo.com/api/profiles
Auth
Authorization: Klaviyo-API-Key {key}
Body format
JSON:API — data.attributes.email + custom properties
Identity key
email, phone_number, or external_id
! Worth knowing: there's no separate "create" vs "update" call — sending the same email twice updates the existing profile rather than erroring or duplicating. If your integration assumes create-fails-on-duplicate, it'll behave differently than expected here.
Source: developers.klaviyo.com/en/reference/create_profile — OpenAPI spec
2
Delete a profile
Permanently erase one profile's data
1 call · from spec
POST https://a.klaviyo.com/api/data-privacy-deletion-jobs
Identifier
exactly one of: email, phone_number, id — sending more than one returns a 400
Execution
Asynchronous — completes after the request returns
Rate limit
burst: 3/s · steady: 60/m — far lower than the profile-write limit
⚠ Irreversible: once a profile is deleted this way, it cannot be restored. Klaviyo keeps a compliance record of the contact info separately, but the profile itself is gone for good.
! Known live issue (Apr 2026): this endpoint has intermittently returned 401 errors immediately after API revision updates, even with a valid key that works fine on other endpoints. If delete calls start failing with 401 right after a revision bump, check scopes before assuming the key is bad.
Source: developers.klaviyo.com/en/reference/request_profile_deletion — OpenAPI spec, cross-checked against Klaviyo Developer Community thread (Apr 15 2026)

Manage Audiences

SKILL
Manage Audiences knows Klaviyo splits this into two genuinely different object types — static Lists and dynamic Segments — with different CRUD support and different traps. Confusing the two costs real time: there are also two different "add to list" endpoints with different consent behavior, confirmed by Klaviyo's own developer community as a recurring source of confusion.
4
Create an audience List · static
New manually-curated audience container
1 call · from spec
POST https://a.klaviyo.com/api/lists
Membership
Manual — grows only when profiles are explicitly added
Source: developers.klaviyo.com/en/v1-2/reference/create-list — OpenAPI spec
5
Add a profile to a list List · static
Two endpoints exist — they behave differently
2 candidate endpoints · from spec
POST /api/lists/{id}/relationships/profiles — adds directly, no consent change
POST /api/lists/{id}/subscribe — routes through opt-in settings
Requires
A profile ID, not an email — if you only have an email, call Get Profiles first to resolve it
⚠ This is the real trap. Klaviyo's own docs recommend using Subscribe Profiles when you're trying to give a profile marketing consent. But if double opt-in is enabled — Klaviyo's default — Subscribe Profiles will return a successful, empty response and add no one until they confirm. The relationships endpoint adds them immediately but does not grant marketing consent. Picking the wrong one looks identical in the response and fails silently.
! Adding a brand-new contact (not yet a profile) to a list is a 2-step sequence: create-or-find the profile first, then add by ID — there's no single call that does both unless you use the separate Bulk Profile Import API.
Source: developers.klaviyo.com/en/reference/add_profiles_to_list, .../subscribe_profiles — OpenAPI spec, cross-checked against Klaviyo Developer Community threads
6
Remove a profile from a list List · static
Membership change only — not a consent change
1 call · from spec
DELETE https://a.klaviyo.com/api/lists/{id}/relationships/profiles
Limit
Max 1000 profile IDs per call
! Removing from a list does not change the profile's subscription/consent status — a profile can be off every list and still technically subscribed. Use the Unsubscribe endpoint if the goal is to stop marketing to them, not just tidy the list.
Source: developers.klaviyo.com/en/reference/remove_profiles_from_list — OpenAPI spec
7
Create an audience Segment · dynamic
Define a rule-based audience
1 call · from spec
POST https://a.klaviyo.com/api/segments
Body
Condition groups (OR within a group, AND across groups) — profile attributes, events, or list membership
Rate limit
burst: 1/s · steady: 15/m · daily: 100/d
! Daily cap is the sharpest limit in this whole spec — 100 segment creations per day, far tighter than anything on the Profiles or Lists side. A script that creates segments in a loop will hit this fast and the failure won't look like a typical rate-limit error pattern until you've burned most of the day's quota.
! This endpoint didn't exist for years — segment creation was dashboard-only, and Klaviyo's own community shows repeated requests for it before it shipped. Worth confirming you're not reading a cached/older doc that still says "not supported."
Source: developers.klaviyo.com/en/reference/create_segment, .../segments_api_overview — OpenAPI spec
—
Add/remove a member Segment · dynamic
There's no endpoint for this — by design
not applicable
— This isn't a missing feature, it's how segments work. Membership is computed continuously from the segment's rule definition — a profile is in or out based on whether it currently matches the conditions, not because anyone called an "add" endpoint. To change who's in a segment, you change the rule (Update Segment), not the membership directly. Looking for a literal add-member call here would be searching for something that was never meant to exist.
Confirmed against: developers.klaviyo.com/en/reference/segments_api_overview and Klaviyo Help Center — segments "update in close to real time" as conditions are met/unmet
BRIDGE Need a fixed copy of who's in a segment right now?
Segment (dynamic) → Snapshot → New List (static)
A segment snapshot captures everyone currently matching the segment's rules into a brand-new static list. The original segment keeps growing and shrinking dynamically; the snapshot list is frozen the moment it's taken. This is the closest thing to "set membership manually" for a segment — you're not editing the segment, you're forking a moment of it into a List.
