Skill architecture — two-layer knowledge delivery
Domain Skill Layer informs steps 02 & 03

Codified prior knowledge about how profile and audience management APIs behave across platforms. Used during Skill Match and HITL Review to surface warnings the spec alone cannot tell you.

Manage Profiles Skill
Knows upsert is idempotent. Knows delete is always async in regulated contexts. Knows "download all" means paginated cursor loop, never a bulk-export endpoint. Flags rate-limit cliff on deletion and 401-post-revision-bump live issue.
3 operations · 4 warnings
Manage Audiences Skill
Knows Lists are static (manual) and Segments are dynamic (rule-based). Flags the two-endpoint list-add consent trap. Flags that segment membership is computed — there is no add/remove-member endpoint by design.
4 list ops · 3 segment ops · 6 warnings
Companion Skill Layer informs steps 04 & 05

Domain knowledge doesn't end at the review screen. Two artifacts carry it forward into MCP generation and live verification, so the model using the MCP server doesn't rediscover the same gotchas at call time.

Enriched OpenAPI Spec
Klaviyo's spec pre-processed before generation. Critical behavioral facts injected into tool description fields on the 10 scoped operations — async delete, consent semantics, pagination requirement, rate limits.
~10 operations enriched · fed to openapi-mcp
Companion Skill File
Full domain knowledge in a Claude skill file, loaded at session start when an LLM drives the MCP server. Covers all operations with per-tool guidance and known live issues. Same facts as HITL review, surfaced at call time.
